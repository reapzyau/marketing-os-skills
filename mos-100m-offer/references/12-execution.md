# Chapter 12 — Execute (The First $100k)

## Hormozi's why
A perfect Grand Slam Offer is worthless if it's never launched. "The first $100k is a bitch — but you gotta do it." Charlie Munger via Hormozi: get to the first $100k by any legitimate means, then the game changes.

## Framework — the execution plan

This chapter is NOT another framework. It's a commitment ritual. The offer is fully designed by now. The remaining work is:

1. **Lock the offer** — no more iteration this cycle. The workbook is the source of truth.
2. **Choose the launch surface** — where the offer goes live (sales page, sales call, DM, email sequence).
3. **Set the first $100k target** — concrete revenue goal with a date.
4. **Identify the constraint** — what's the bottleneck in the funnel? Traffic? Booking rate? Show-up rate? Close rate? Fulfillment capacity?
5. **Plan the next iteration** — what would trigger version 2? (After N customers? After N weeks?)

## The 5-question commitment

Walk the user through these in order:

**Q1: Launch surface.**
- Where does the offer go live? (sales page / DM funnel / call script / email sequence / live event)
- Is the surface built, or is building it the first task?

**Q2: First $100k target.**
- Concrete revenue number.
- Specific deadline.
- Number of customers to hit it (revenue ÷ offer price).

**Q3: Funnel math.**
- At the chosen offer price, what funnel is required?
  - Customers needed = Target ÷ Price
  - Calls / consults needed = Customers ÷ Close Rate
  - Leads needed = Calls ÷ Booking Rate
  - Traffic needed = Leads ÷ Opt-in Rate
- This identifies the constraint upfront.

**Q4: The constraint.**
- Which funnel stage is most likely the bottleneck given current capacity?
- What's the single experiment that would unlock the most volume there?

**Q5: Iteration trigger.**
- After what milestone will the offer get a v2? (e.g., after 10 customers · after 4 weeks · after first 3 testimonials)
- Schedule it now so iteration doesn't get deferred indefinitely.

## Diagnostic questions (ask the user)

Use the 5 questions above as the chapter's conversation. Don't introduce new frameworks — Hormozi is explicit that Chapter 12 is the action chapter, not another model.

## Validation criteria (what "good" looks like)
- A specific launch surface named, with build status acknowledged
- A first $100k target with a concrete deadline
- Funnel math worked out (customers / calls / leads / traffic, with rough conversion rates)
- The constraint named with a single experiment to address it
- An iteration trigger scheduled (when, what triggers)
- A reference to `/mos-money-models` as the next skill (upsells, downsells, continuity)

Push back if:
- "I'll launch when it's ready" — set a deadline, then work backward
- No funnel math — the offer might be priced for a funnel the user doesn't have
- Constraint is "marketing" — too vague; push for the specific stage and experiment
- No iteration trigger — version 2 won't happen unless it's scheduled

## Pitfalls (Hormozi's warnings)
- **"I'll launch when it's ready."** It will never be ready. Set the date, work back.
- **Skipping funnel math.** The offer's price implies a funnel. If the funnel doesn't exist at scale, the price doesn't work.
- **Vague constraint.** "Marketing" / "Sales" — too broad. Name the stage. Name the experiment.
- **No iteration trigger.** Without one, v1 becomes v∞ and the offer never compounds.
- **Forgetting to run the money model.** Hormozi wrote Book II on this. A Grand Slam Offer without upsells/continuity/downsells leaves enormous money on the table. The next skill in the chain is `/mos-money-models`.

## Workbook output expected
A launch plan: specific surface, first $100k target with date, funnel math, named constraint, single unlock experiment, and a scheduled iteration trigger. Plus a pointer to `/mos-money-models` as the immediate next move.
